# Apple Mail 実機受け入れ手順

状態: **未実行**。Mailの既存データを開発エージェントが自動で選択・読み取り・撮影・書き換える手順ではありません。利用者が架空メールを用意し、アプリ内で明示実行します。送信操作はどの試験でも禁止です。

**v0.1.5では診断の通常UIを外しています。以下は診断を明示操作で再公開する際の受け入れ項目で、現在の配布版から手順3・4は実行できません。** 診断コードは保持していますが、通常の「Mailに配置」は未検証のまま無効です。

## 準備と最初の1通

1. `scripts/build-app.sh` で署名付き.appを作り、`open build/HarborReply.app` で開く。
2. 利用者がテスト専用のメールを用意し、Mailで開くかテスト用メールボックスに取り込む。全てのアドレスに `.invalid` を使用し、件名は `[HarborReply TEST]` とする。配布ZIPにテストメールは同梱しない。開発リポジトリの `fixtures/mail-test.eml` はテスト用に限って使用できる。既存の実メールを移動・削除しない。
3. 「Mail診断」で「返信」を選択する。Mail側で上記1通だけを選択する。
4. 診断画面の読み取り・下書き作成・固定文挿入の説明と、下書きのサーバー同期の可能性を確認し、チェックして「固定文でMail往復を診断」。Automationを求められたら利用者自身が通常のOSフローで決める。
5. アプリは選択→アカウント/Message-ID/body固定→Mail自身のreply→返されたoutgoing object追跡→先頭段落追加→本文・宛先・署名名を照合する。
6. 成功でもMailで目視確認し、下の表を埋める。送信しない。作成したテスト下書きの処分は利用者が行う。

アプリの診断文字列にAppleScript風の行があります。これは引用符・改行・コード風の文字列が**データとして挿入される**ことを確認するための架空テストです。

## 失敗時の記録

本文・メールアドレス・船名を含まない形で記録:

```text
OS / Mail / Xcode / .app署名:
fixture ID:
操作: capture / create / insert / post-check
表示されたエラー番号:
下書きができたか:
固定文が部分的に入ったか:
署名・引用・画像・宛先・返信関係の保持:
取消や途中編集で止まったか:
```

9101選択数、9102選択メールサイズ、9103追跡下書きなし、9104同一要求の不確実な作成再試行、9105対象変更、9106下書き変更。その他の負の番号はMail/Apple Eventsの実エラーです。アプリはエラー文字列の本文をログへ出しません。

部分書き込みの可能性がある場合、同じ下書きへ自動再試行しません。失敗したからといって全本文置換・座標クリック・クリップボード貼付へ切り替えません。利用可能な代替はアプリ内プレビューと人によるMail編集です。

## 通常挿入を開ける条件

全項目の実機証拠を集め、書式/暗号設定/編集競合を検出できない箇所を解消すること。フラグを切り替えるだけでは合格にしません。現版は通常・自動挿入が閉じた状態を維持します。
